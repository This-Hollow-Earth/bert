# BERT Assessment Questionnaire (v1)

Answer once per Module. Pick the paragraph that sounds closest to how this
Module actually works today — not how you wish it worked.

## Question: Which of these sounds most like this Module?

**A — Every request starts from scratch.**
Every time someone needs something from this Module, it's handled
individually, from the ground up. The work depends heavily on whichever
senior person handles it. You can't easily predict how long a request will
take or how much it will cost. The same kind of request comes up every few
months, solved fresh each time, with nothing carried over from the last one.

**B — We've built internal tools, but a person still runs them.**
You've noticed the same requests coming up again and again, so you've built
scripts, templates, or internal tools that make handling them faster. But
someone still has to run those tools by hand for every request. People are
starting to ask if they can just use the tool themselves, or subscribe to it
directly, instead of asking a person to run it for them.

**C — People think they're self-serve, but someone's still behind the curtain.**
On the surface it looks like people can help themselves. In reality, your
team is still configuring things manually for every request, patching
exceptions on the fly. Getting set up takes weeks, not minutes. Feedback from
different requesters gets stuck between "is this a bug" and "is this a
missing feature," with no clear owner. Every additional requester adds real
work for your team, not just a checkbox.

**D — People mostly serve themselves, but the biggest requests still need us.**
Most people can get what they need from this Module without help; you can
reasonably predict how much this will cost and how long it will take. But
your largest, highest-stakes requests still need hand-holding, onboarding
support, or a dedicated point of contact. Every one-off exception you grant
here risks dragging things back toward C.

**E — People serve themselves, at near-zero effort from us.**
Someone new can get what they need from this Module without ever talking to
your team. The cost of serving one more person is close to zero. Your team's
time goes toward handling volume, not handling complexity or exceptions.

## Reporting the result

Report the chosen stage as the Module's placement. Regardless of which
answer was picked, always also show the **next stage up** as context — e.g.
if the Module answered C (Hybrid), show what D (Big Head SaaS) looks like as
the next rung, without computing or claiming any numeric "distance" to it.
This is deliberately not a score: it's "here's where you are, here's what's
next," matching the essay's own framing that maturity stages are a map, not
a judgement.

## Known v1 limitation

Stage 2 (Automated Consultancy) does not distinguish between 2a (vertical /
efficiency automation) and 2b (horizontal / subscription automation) — the
source essay treats these as a fork in direction, not a rung on a ladder,
which doesn't fit a single linear multiple-choice option. Flagged as a
fast-follow, not resolved here.
